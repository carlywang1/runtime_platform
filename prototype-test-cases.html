💡 交互说明

  • 触发时机：用户说"当前测试没有问题了"后，Steward 自动生成测试用例（而非直接进入 publish）
  • 生成逻辑：Steward 根据 Agent 的 capabilities、instructions、output_schema 自动生成覆盖各分支的测试用例
  • 运行方式：全选 + Run All 批量跑，或逐个勾选运行。运行时左侧对话区自动发起执行（和 debug run 一致）
  • 运行过程：左侧对话区按顺序展示每个 case 的执行过程（typing → exec-log），跑完一个接着下一个，右侧面板同步更新状态
  • 编辑用例：每个 case 有 Edit 按钮，点击后 Input 和 Expected 字段变为可编辑，修改后 Save 保存
  • 结果判定：对比 Expected 和 Actual，字段匹配则 PASS，不匹配则 FAIL
  • 失败处理：如果有 FAIL 的用例，Steward 会建议修复方向，用户可选择修复后重跑或忽略继续
  • 通过后：全部 PASS 后，Steward 提示"测试全部通过，可以进入发布流程"，展示 Chips 引导进入 publish
  • 右侧面板：复用现有的 PanelCard 组件位置（和 BuildAgentPanel / DebugRunPanel 同层级切换）

🔄 状态机变更

现有流程: step12("当前测试没有问题了") → step13(配置正式环境) → step14 → step15(发布) 新流程: step12("当前测试没有问题了") → step12.5: Steward 生成测试用例，右侧面板切换为 TestCasesPanel → step12.6: 用户选择 Run All 或逐个 Run → step12.7: 运行中（左侧对话 + 右侧状态更新） → step12.8: 全部 PASS → Steward 提示可以发布 | 有 FAIL → Steward 建议修复，用户可选择： a) 修复 Agent → 重跑失败用例 b) 忽略继续发布 → step13(配置正式环境) → ... Chips 变化: step12 之后的 Chips: 旧: [配置正式环境参数] 新: [生成测试用例] [跳过测试，直接发布] 测试阶段的 Chips: [Run All Test Cases] [添加自定义用例] [跳过，直接发布] 全部 PASS 后的 Chips: [进入发布流程] [再跑一轮] [添加更多用例] 有 FAIL 时的 Chips: [修复并重跑失败用例] [忽略失败，继续发布] [查看失败详情]

interface TestCase { id: string; name: string; // 用例名称 description?: string; // 用例描述 input: { from: string; // 发件人 subject: string; // 邮件主题 body: string; // 邮件正文 }; expected: { classification: string; // 期望分类 draft_reply_contains?: string; // 期望回复包含的关键词 requires_followup: boolean; // 是否需要追问 followup_question?: string; // 追问内容 routed_to?: string; // 路由目标 }; actual?: { // 运行后填充 classification?: string; draft_reply?: string; requires_followup?: boolean; followup_question?: string; routed_to?: string; error?: string; }; status: 'pending' | 'running' | 'pass' | 'fail'; selected: boolean; // 是否被选中 } interface TestCasesPanelState { cases: TestCase[]; totalCount: number; passCount: number; failCount: number; runningCount: number; pendingCount: number; }
